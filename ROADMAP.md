# Roadmap

The entry point to the plan of Craft Yourself. The plan itself is data in
[`roadmap/`](roadmap/) — one file per roadmap, every item with a stable id —
and everything below the summary is generated from it. Nothing here repeats
an item's content: follow the links.

## Roadmaps

| Roadmap | Prefix | What it covers |
|---|---|---|
| [Product](docs/roadmaps/product.md) | `PRD` | What the learner gets: goals, scenarios, user-facing features |
| [Technical](docs/roadmaps/technical.md) | `TEC` | Architecture, components, technical debt |
| [Learning](docs/roadmaps/learning.md) | `LRN` | Learning methodology: assessment, competencies, adaptation |
| [Research](docs/roadmaps/research.md) | `RND` | Hypotheses and experiments with accept/reject criteria |
| [Infrastructure & Security](docs/roadmaps/infrastructure.md) | `INF` | CI, sandbox and engineering tools, security, data |
| [Releases](docs/roadmaps/releases.md) | `REL` | Versions in shipping order and their scope |

Across all of them: [dependencies](docs/roadmaps/dependencies.md) (graph,
cycles, bottlenecks) and [metrics](docs/roadmaps/metrics.md) (progress,
blocked work, debt, criteria, effort).

## Changing the plan

```sh
$EDITOR roadmap/product.toml                # or any roadmap file
cargo run -p est-roadmap -- check           # integrity rules R01–R14
cargo run -p est-roadmap -- render          # regenerate docs/roadmaps and the summary
cargo run -p est-roadmap -- metrics         # progress, blocked and overdue items for today
```

`cargo test --workspace` (and so CI) fails when the data has an error or a
generated view is out of date. Commit the data and the rendered views together.
