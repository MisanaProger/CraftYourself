# Аудит репозитория и gap analysis (Phase 0)

- **Дата:** 2026-11-21, ветка от `15ef420` (после PR #8).
- **Основание:** ТЗ «CraftYourself — Functional Expansion & Roadmap System
  Refactoring», v1.0.
- **Элемент roadmap:** [TEC-081](../roadmaps/technical.md#tec-081).

Статусы: **есть** — реализовано и покрыто тестами; **частично** — есть
основа, требования ТЗ выполнены не полностью; **нет** — отсутствует.
Наличие модуля или интерфейса не считалось реализацией (ТЗ §11): для
каждого «есть» указан код и проверка.

(fmt, clippy, тесты, фронтенд, desktop). Этапы 0–7 и 9 спецификации v0.3
реализованы, этап 8 и desktop — частично. Инвентаризация реализованного —
элементы со статусом Done в программах
[PRD-001](../roadmaps/product.md#prd-001),

[LRN-001](../roadmaps/learning.md#lrn-001),
[INF-002](../roadmaps/infrastructure.md#inf-002),
[INF-012](../roadmaps/infrastructure.md#inf-012),
[INF-031](../roadmaps/infrastructure.md#inf-031).

Важно для ТЗ: значительная часть «доказательной оценки» уже существует —
Skill Matrix оценивается только по наблюдаемым свидетельствам, с пятью
измерениями (Theory, Practice, Diagnosis, Transfer, Independence),
статусами доказательности и уверенностью; ADI учитывает уровни помощи и
скопированный код. Расширение строится на этом, а не рядом.

## 8. Архитектурные ограничения для новой работы

Из `AGENTS.md`, обязательны для всех элементов TEC/LRN/INF:

1. **Политика в коде.** Бюджет подсказок, адаптация сложности, путь
   обучения решаются в `est-ai-policy` / `est-application` / чистых crates до
   вызова модели. Модель может предлагать (класс ошибки, черновик задачи,
   формулировку объяснения), решает код.
2. **L0 и согласие.** Новые механики (бюджет подсказок, контрольные задачи,
   сгенерированные Issue) не поднимают уровень и не обходят согласие; любая
   новая Issue начинается с L0.
3. **Только наблюдаемые события.** Новые свидетельства — из событий,
   тестов, проверенных ответов; самооценка и рефлексия — данные, а не
   доказательство, пока не проверены. ADI и Skill Matrix независимы;
   отсутствие данных — `not_assessed`.
4. **Песочница.** Тестовые наборы, PBT, замеры сложности и статический
   анализ выполняются только в `est-sandbox` с теми же флагами.
5. **Миграции только добавляются**; экспорт и удаление охватывают новые
   таблицы; секретов нет нигде.
6. **Порты и слои.** Новая инфраструктура — порт в
   `est-application/src/ports.rs` и адаптер; доменные правила в `est-domain` /
   чистых crates с модульными тестами; пользовательские сценарии — тест в
   `learning_loop.rs`; строки UI — в `en`, `ru`, `uz`.
