# ADR-0002: Хранимый журнал свидетельств (evidence ledger)

- **Статус:** Proposed
- **Дата:** 2026-11-21
- **Элементы roadmap:** TEC-011 (TEC-012 … TEC-016), TEC-017, LRN-011

## Контекст

Skill Matrix сейчас вычисляется при каждом запросе
(`est-application/src/skills.rs`, `skill_evidence`): из `lesson_results`
(миграция 0007), `learning_progress` и `session_summaries` (0006) собираются
структуры `est_discipline::Evidence`, затем `transfer` и `assess`.
Свидетельства нигде не хранятся. Последствия:

1. **Невоспроизводимость.** Навыки урока читаются из `program.toml` в момент
   оценки (комментарий миграции 0007), навыки Issue — из `tasks.skill_refs`
   или правил `infer_skills`. Изменение каталога, программы или правил
   незаметно меняет прошлые оценки (ТЗ 2.1: «оценки должны быть
   воспроизводимыми»; ТЗ 4.4).
2. **Нет полей ТЗ 2.1.** У `Evidence` нет типа свидетельства (7 типов),
   уровня помощи как отдельного поля, результата проверки, достоверности,
   ссылки на исходный контекст (есть только `reference` = сессия или
   `program/lesson`), версии правил.
3. **Нет происхождения (ТЗ 4.4).** Нельзя ответить, какие события привели к
   оценке и какой версией правил она получена.
4. Будущие подсистемы (retention, misconceptions, путь обучения, журнал)
   нуждаются в истории свидетельств, а не в последнем снимке.

## Решение (предлагаемое)

1. **`EvidenceRecord` в `est-domain`** с полями ТЗ 2.1 и `rule_version`
   (спецификация: `docs/specifications/evidence-assessment.md`).
2. **Выведение — чистые правила** в `est-discipline` (без I/O, без модели,
   без ADI): из завершённой сессии, попытки теста, результата артефакта,
   контрольной задачи. Одна Issue → несколько записей.
3. **Хранение — append-only** таблица новой миграции через порт
   `EvidenceRepository`. Запись не меняется; исправление — новая запись со
   ссылкой `supersedes`. Удаление данных ученика (диалога, всех данных)
   удаляет записи — приватность важнее неизменяемости.
4. **Записи создаются в момент наблюдения** (завершение сессии, попытка
   теста) с навыками, разрешёнными на этот момент, и версией каталога.
   Последующее изменение `program.toml` не меняет записанное.
5. **`assess` читает записи**, а не пересобирает их; функция и её версия
   остаются чистыми и тестируемыми.
6. **Backfill** существующих данных один раз, с `rule_version = "backfill-1"`;
   результат совпадает с нынешней матрицей (тест на фикстурах).

## Рассмотренные альтернативы

- **Оставить вычисление при запросе и хранить только снимки оценок.**
  Проще, но снимок не объясняет себя (какие свидетельства, почему этот тип), а
  будущим подсистемам всё равно нужна история.
- **Event sourcing всего приложения.** Избыточно: события сессий уже
  хранятся (`session_events`), нужен проекционный журнал одной области.
- **Хранить свидетельства в JSON внутри `session_summaries`.** Не покрывает
  уроки и контрольные задачи; запросы по навыку становятся сканом.

## Последствия

- Новая миграция (append-only, правило 8); экспорт и удаление данных
  включают записи.
- Skill Matrix при равных данных не меняется (проверяется backfill-тестом).
- Объяснение оценки (PRD-032) и provenance (TEC-018) становятся запросом к
  журналу.
- Принять решение (статус Accepted) — при старте TEC-014; до того возможны
  уточнения полей по результатам RND-007.
