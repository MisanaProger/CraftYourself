# Спецификация: контроль сохранения знаний

- **Статус:** Draft
- **ТЗ:** 2.3 · **Roadmap:** LRN-018 (LRN-019 … LRN-021), TEC-044, PRD-043, RND-008

## Цель

Освоение динамично: навык перепроверяется, а его устойчивость зависит и от
времени, и от числа учебных взаимодействий после последней проверки.
Сейчас есть только фиксированное правило `needs_reassessment` через 180 дней
(`est_discipline::STALE_AFTER_DAYS`).

## Модель устойчивости (LRN-019)

Для навыка `s` по журналу свидетельств:

- `last_check` — последнее свидетельство High/Medium с баллом ≥ 60;
- `stability S` (дни) — растёт с каждой успешной перепроверкой, разнесённой
  во времени: `S₀ = 7`, после успешной проверки через интервал `Δ ≥ S/2`
  `S ← S · k` (`k = 2.0` в версии `retention-1`); неудачная проверка
  `S ← max(S₀, S/2)`;
- **удержание** `R = exp(−t / S) · exp(−n / N)`, где `t` — дни с
  `last_check`, `n` — число завершённых Issue и уроков *по другим* навыкам
  дисциплины после неё, `N = 12`. Это та же идея двойного затухания, что в
  ADI (`est_dependency::decay_weight`), но для навыка.

Параметры (`S₀`, `k`, `N`) — версия правил `retention-1`; их калибровка —
эксперимент [RND-008](../roadmaps/research.md#rnd-008). До результата
используются значения выше, помеченные в provenance.

## Сигналы забывания (LRN-020)

Навык получает `needs_reassessment`, если:

- `R < 0.5`; или
- проваленная проверка навыка со статусом `established`; или
- Issue по навыку завершена с помощью L3+ при прежнем самостоятельном
  решении (`independent_solution`).

Это расширяет правило 180 дней: оно остаётся как верхняя граница.
Причина статуса сохраняется и показывается ученику.

## Планирование (LRN-021, TEC-044)

- Очередь перепроверки: навыки с `needs_reassessment` или `R < 0.7`,
  по возрастанию `R`, не больше 3 одновременно.
- Вид проверки: короткая контрольная (тест, задача с примерами) или
  применение в новом контексте, если у навыка ещё нет Transfer.
- Контрольная задача — обычная Issue: начинается с L0, её результат —
  свидетельство `control_task`. Помощь не запрещена, но меняет тип
  свидетельства (`hinted_solution`), а не уровень доступа.
- Планировщик работает по запросу (`GET /learning/reviews`), фоновых задач
  в Local Edition нет.

## Тестируемость

Модель — чистые функции в `est-adaptive` (TEC-042) с модульными тестами на
фиксированных историях: убывание `R` со временем и с числом
взаимодействий, рост `S` после разнесённых проверок, сброс после неудачи.
