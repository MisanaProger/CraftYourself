# Спецификация: инженерные инструменты проверки

- **Статус:** Draft
- **ТЗ:** 3.1–3.6 · **Roadmap:** INF-010 (INF-011 … INF-023), TEC-020

Все инструменты выполняются только в `est-sandbox` с текущими флагами
(`--network none`, `--cap-drop ALL`, `--read-only`, `no-new-privileges`,
лимиты, read-only рабочий каталог) — AGENTS.md, правило 3. Доступ к сети —
только с разрешения ученика на запуск.

## 3.1 Code Sandbox — есть (INF-012)

Требования ТЗ выполнены `est-sandbox`. Открыто: опция gVisor/Kata
(INF-013), пресеты образов и шаг загрузки зависимостей (INF-014),
интеграционные тесты в CI (INF-005).

## 3.2 Automated Testing (INF-016)

Манифест получает наборы по видам:

```toml
[[tests.suite]]
kind = "edge"        # prepared | edge | invalid-input | stress | reference
command = "pytest tests/edge"
hidden = true        # копируется в песочницу только на время прогона
time_limit_seconds = 30
```

Скрытые наборы, как ответы тестов (правило 9), не попадают в рабочий
каталог ученика. Сравнение с эталоном (INF-019): эталон и решение
запускаются на одинаковых входах, выводы сравниваются.

## 3.3 Property-Based Testing (INF-020)

Генератор входов с фиксированным seed (seed пишется в результат для
воспроизводимости) и наивная реализация; пример ТЗ — дерево отрезков против
массива на случайных последовательностях запросов.

## 3.4 Complexity Analysis (INF-021)

Замер времени на ряде размеров входа, подбор модели (`1, log n, n, n log n,
n², …`) и сравнение с заявленной сложностью. Отчёт разделяет
теоретическую оценку и измерение; шумные замеры помечаются.

## 3.5 Static Analysis (INF-022)

clippy, ruff, clang-tidy, eslint в образах языков; находки сводятся к
категориям ТЗ (ошибки, небезопасные конструкции, соглашения, подозрительные
места, структура). Это свидетельства Medium для навыков сопровождаемости.

## 3.6 Reproducible Tasks (TEC-020)

Попытка хранит версии условия, тестов, критериев, digest образа, параметры
генерации (seed) и версию правил оценки.
