# Спецификация: выявление устойчивых заблуждений

- **Статус:** Draft
- **ТЗ:** 2.4 · **Roadmap:** LRN-028 (LRN-029 … LRN-031), TEC-051, RND-009

## Модель

- **Класс ошибки** (`ErrorClass`, LRN-029) — элемент таксономии дисциплины,
  привязанный к навыкам: `algorithms/edge-cases: empty-input`,
  `algorithms/correctness-proof: wrong-invariant`,
  `numerical-methods/stability: catastrophic-cancellation`,
  `data-structures/segment-tree: off-by-one-range` …
- **Наблюдение ошибки** — класс, навык, источник (упавший тест с именем,
  замечание ревью коммита, неверный ответ теста с помеченным вариантом),
  дата, контекст, достоверность.
- **Заблуждение** — класс, наблюдаемый у ученика систематически.

## Классификация (TEC-051)

1. Правила кода: варианты ответов тестов помечены классами
   (`quizzes/*.toml`), тестовые наборы манифеста — классами по именам
   тестов, правила ревью — своими классами.
2. Модель может *предложить* класс для упавшего теста без пометки; он
   принимается, только если совпадает с классом, допустимым для навыков
   задачи, и сохраняется с `reliability = low` и пометкой модели
   (эксперимент RND-009 решает, нужен ли этот шаг).

## Систематическая или случайная (LRN-030)

Заблуждение, если класс наблюдался в ≥ 2 разных объектах (Issue, уроки)
за последние 10 объектов по навыку, причём хотя бы одно наблюдение —
High/Medium. Одно наблюдение — случайная ошибка.

## Исправление (LRN-031)

Заблуждение `resolved`, когда после последнего наблюдения есть ≥ 2
независимых (`independent_solution` или `control_task`) свидетельства по
навыку без этого класса. История (обнаружено → корректирующая задача →
исправлено / повторилось) хранится и передаётся в генератор пути
(LRN-025) и журнал (TEC-048).
